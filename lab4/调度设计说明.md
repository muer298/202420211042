# Lab4 调度设计说明

## 个人策略

学号 `2024302111042` 的 `LAB4_POLICY_ID = 2`，因此采用四级 MLFQ。进程从 0 级开始，同级按轮转扫描；每次用满当前时间片后降一级，最低到 3 级。时间片依次为 `LAB2_TICK × 1、2、4、8`，本项目 `LAB2_TICK=2`，所以四档分别为 2、4、8、16 个时钟中断。

本实现沿用 Lab2 的 tick 口径：定时器每次触发使 `ticks` 增加 1，`LAB2_TICK` 表示最高优先级时间片包含的中断次数。主动睡眠后唤醒保留原队列等级；只有用完时间片才降级。`setickets` 保存用户设置值，但不影响本人的 MLFQ 策略。

## 上下文与状态切换

每个进程有自己的内核 `context`、页表、trapframe 和内核栈。调度器与进程之间通过 `swtch.S` 保存/恢复 `ra`、`sp`、`s0`–`s11`。调度器持有进程锁将进程置为 `RUNNING` 后切入；进程因时钟片用尽、等待输入、等待子进程或 `pause` 而切回时，先在锁保护下更新状态。新进程第一次运行从 `forkret` 进入用户返回路径。

`sleep`/`wakeup` 通过 channel 等待和唤醒进程；`wait` 在子进程退出时被唤醒，并通过 `copyout` 回写退出码。退出进程切换到调度器后再由父进程回收，避免释放仍在使用的内核栈。

## 观测与验证

- `schedstat(pid, &cpu_ticks, &last_slice_ticks)`：查询累计用户态定时器 tick 数和最近一次运行片长度；`pid=-1` 查询自身。
- `time_rdtime()`：读取 RISC-V `time` CSR 计数，不等同于软件 tick。
- `setickets(n)`：`n<1` 返回 `-1`，否则记录设置并返回 0。
- `make test`：包含 Lab3 回归和 Lab4 的 `bench`、`mlfq_test` 检查。
- `mlfq_test` 通过 `schedstat` 观测 2/4/8/16 四种时间片，并验证定时器统计、系统调用与退出码。
